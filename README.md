## 前言

網站中整理了六種排序法，分別是氣泡、選擇、插入、合併、快速與堆積排序。  
內容包含每個演算法的基本原理、操作方式，以及時間複雜度(執行時間)與空間複雜度(需佔用多少RAM)分析，並設計最差情況進行模擬，比較各排序法的差異。  


## 1. 氣泡排序法 (Bubble Sort)

### 基本原理
透過相鄰元素兩兩比較，若順序錯誤就交換，讓較大值在每一輪中逐步「浮」到陣列尾端。由於每輪都會確定一個最大值的位置，因此未排序區間會持續縮小；若某一輪完全沒有交換，代表序列已經有序，可提前結束。

### 操作方式
1. 從頭開始比較相鄰兩元素。
2. 若前者大於後者則交換。
3. 一輪結束後，最大值會落在最右側。
4. 重複上述流程，逐步縮小未排序區間，直到完成排序。

### 時間複雜度分析
- 最佳情況：O(n)（已近乎有序且有提早結束機制）
- 平均情況：O(n^2)
- 最差情況：O(n^2)

### 空間複雜度分析
- O(1)（原地排序）



## 2. 選擇排序法 (Selection Sort)

### 基本原理
每一輪從未排序區間中找出最小值，放到已排序區間的尾端，核心在於「選出正確元素再放定位」。它不追求每次比較都改善局部順序，而是用一輪掃描決定一個最終位置，因此比較次數固定，但交換次數通常較少。

### 操作方式
1. 假設目前索引 i 為待放置位置。
2. 在區間 [i, n-1] 找到最小元素索引。
3. 將最小元素與索引 i 的元素交換。
4. i 右移，重複直到陣列排序完成。

### 時間複雜度分析
- 最佳情況：O(n^2)
- 平均情況：O(n^2)
- 最差情況：O(n^2)

### 空間複雜度分析
- O(1)（原地排序）





## 3. 插入排序法 (Insertion Sort)

### 基本原理
將資料分為「已排序」與「未排序」兩區，逐一把未排序元素插入已排序區的正確位置。這種做法類似打撲克牌時整理手牌：每拿到一張新牌，就往前找到應在的位置插入，因此在資料本來就接近有序時，移動成本會明顯降低。

### 操作方式
1. 將第一個元素視為已排序。
2. 取下一個元素作為 key。
3. 由右往左比較已排序區，將大於 key 的元素右移。
4. 把 key 插入空出的位置。
5. 重複直到全部元素處理完畢。

### 時間複雜度分析
- 最佳情況：O(n)（資料已近乎有序）
- 平均情況：O(n^2)
- 最差情況：O(n^2)

### 空間複雜度分析
- O(1)（原地排序）





## 4. 合併排序法 (Merge Sort)

### 基本原理
採用分治法：先將陣列遞迴切分成更小子陣列，直到每段都可視為已排序，再透過合併步驟回組成完整有序陣列。其重點在於「分解問題」與「線性合併」兩件事，藉由規模持續對半縮小來維持穩定的效率。

### 操作方式
1. 將陣列切成左右兩半，直到子陣列長度為 1。
2. 兩兩合併子陣列，合併時維持排序。
3. 重複合併，直到回到完整陣列。

### 時間複雜度分析
- 最佳情況：O(n log n)
- 平均情況：O(n log n)
- 最差情況：O(n log n)

### 空間複雜度分析
- O(n)（需要額外暫存空間）





## 5. 快速排序法 (Quick Sort)

### 基本原理
選定基準值 (pivot)，將小於 pivot 的元素放左側、大於 pivot 的元素放右側，讓 pivot 一次就落到最終排序位置，接著再遞迴處理左右子區間。它的效率關鍵在分割是否平均：分割越平衡，遞迴層數越接近對數階，整體效能就越好。

### 操作方式
1. 選擇 pivot（可用首/尾/隨機/三數取中）。
2. 進行分割 (partition)，讓 pivot 置於最終排序位置。
3. 對 pivot 左右兩區分別遞迴排序。
4. 子陣列長度小於等於 1 時結束。

### 時間複雜度分析
- 最佳情況：O(n log n)
- 平均情況：O(n log n)
- 最差情況：O(n^2)（分割極不平均時）

### 空間複雜度分析
- 平均：O(log n)（遞迴堆疊）
- 最差：O(n)





## 6. 堆積排序法 (Heap Sort)

### 基本原理
先將資料建成最大堆 (Max Heap)，利用「父節點大於子節點」的堆特性，讓最大值永遠位於堆頂。之後每次將堆頂最大值與尾端交換並縮小堆範圍，再重建堆性質，重複此流程即可逐步完成由小到大的排序。

### 操作方式
1. 先將陣列轉為最大堆。
2. 將堆頂（最大值）與尾端交換。
3. 縮小堆範圍，對根節點執行 heapify。
4. 重複直到堆大小為 1。

### 時間複雜度分析
- 建堆：O(n)
- 整體排序：O(n log n)（最佳/平均/最差皆同階）

### 空間複雜度分析
- O(1)（原地排序，不計遞迴實作細節）

## 綜合比較

| 排序法 | 最佳時間 | 平均時間 | 最差時間 | 空間複雜度 | 穩定性 |
|:---:|:---:|:---:|:---:|:---:|:---:|
| 氣泡排序 | O(n) | O(n^2) | O(n^2) | O(1) | 穩定 |
| 選擇排序 | O(n^2) | O(n^2) | O(n^2) | O(1) | 不穩定 |
| 插入排序 | O(n) | O(n^2) | O(n^2) | O(1) | 穩定 |
| 合併排序 | O(n log n) | O(n log n) | O(n log n) | O(n) | 穩定 |
| 快速排序 | O(n log n) | O(n log n) | O(n^2) | O(log n)（平均） | 不穩定 |
| 堆積排序 | O(n log n) | O(n log n) | O(n log n) | O(1) | 不穩定 |

###
1. 小型且近乎有序資料：插入排序通常表現良好。
2. 需要穩定排序：可優先考慮合併排序（但需額外空間）。
3. 追求平均效率與實務常用：快速排序常有不錯表現，但需避免最差情況。
4. 需要穩定的 O(n log n) 上界且原地排序：堆積排序是可行選項。
5. 氣泡與選擇排序概念單純，適合教學，但在大量資料時效率較差。


## 結論
1. 實驗結果顯示，當資料量增加時，(O(n^2)) 演算法的耗時成長遠快於 (O(n \log n))，證明時間複雜度在實務上具有明顯影響。
2. 快速排序在最差情況下表現接近 (O(n^2))，遠大於一般情況。
3. 合併排序與堆積排序在大資料量下呈現較穩定的成長趨勢，適合需要較佳效能上界的情境。
